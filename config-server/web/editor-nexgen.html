专用客户端模式
关闭
开启前请先完成后端面板对接
此开关只会让客户端进入“客服端专用模式”，不会自动修改 XBoard/V2Board 后端订阅逻辑。请先在服务器完成后端补丁、节点标签配置与缓存清理，再回来开启此项。
完成改造后会有什么作用
  • 开启专用模式的客户端会使用专用客户端标识拉取订阅，只获取带 客服端专用 标签的节点。
  • 普通第三方客户端继续走普通订阅逻辑，只获取未打 客服端专用 标签的节点。
  • 可以把客服端入口与普通入口分开，降低第三方客户端误用、分享扩散或入口泄露的风险。
  • 适合把内部客服端、定制客户端、专用节点与普通公开节点隔离管理。
后端如何开启专用客服端模式
  1. 登录部署面板的服务器，执行一键脚本：bash <(curl -fsSL https://raw.githubusercontent.com/q42602736/scripts/main/panel_patch.sh)
  2. 按提示选择面板类型和站点目录，例如 /www/wwwroot/你的站点目录。
  3. 等待脚本自动打补丁并清理 Laravel 缓存；如果仍未生效，再手动重载 PHP-FPM 或重启容器刷新 OPcache。
  4. 进入你的面板后台，把需要仅给客服端使用的节点打上标签 客服端专用。
  5. 需要给普通第三方客户端继续使用的节点，不要打这个标签；这样两类客户端拉取到的节点会自动分开。
  6. 完成以上步骤后，再回到这里打开“专用客户端模式”，重新生成配置并打包客户端。
重要提醒
未完成后端改造前请不要直接开启，否则可能出现订阅失败、返回错误格式配置、专用节点不生效等问题。当前补丁脚本仅支持 XBoard 与 V2Board，暂不支持 SSPanel 系面板。
仅在关闭“专用客户端模式”时生效；专用模式请填写下方“专用模式订阅 UA”。
仅在开启“专用客户端模式”后显示，选填。不填写时会回退到默认值 XBoardMihomo/1.0。可完全自定义，但必须与你给后端补丁脚本输入的专用客户端 UA/标识保持一致。
SSPanel-Metron 专属配置
SSPanel-Metron 的 Clash/Mihomo 订阅通常需要 clash=1。留空时客户端默认使用 clash=1，也可填写 clashmeta=1 或其他面板需要的查询参数。

远程配置文件

按配置项生成 remote.config.json，可直接下载使用；如需更高安全性，再执行 AES-256-GCM 加密。

操作流程
1. 填写配置项直接填写面板类型、官网地址、站点分组名称、站点列表和静态更新配置，系统会实时生成 remote.config.json。
2. 检查源码预览上方“remote.config.json 源码”页签会实时显示最终 JSON，提交前可先核对格式和字段。
3. 按需加密配置文件 推荐操作首次加密建议点击“生成密钥并加密配置文件”；如果是后续更新配置，直接填写已保存的密钥，再点击“使用当前密钥加密”。
4. 保存密钥并下载配置文件如果不需要加密，可直接下载 remote.config.json；若已加密，请保存好密钥，并将它填写到远程配置源的“加密密钥（可选）”中。
remote.config.json 配置项
请选择当前站点使用的面板类型；如果是 xiaov2board，请选择 v2board。
这里填写软件内“官网入口”打开的地址，通常就是你的主站域名，例如 https://your-site.com 。
这里非常重要：这个值必须与基础设置里的“站点分组名称”完全一致，包括大小写。建议两个地方都直接填写品牌名；remote.config.json 会用它作为 panels 的键名，如果不一致，软件可能无法正确识别站点，甚至无法正常启动。
站点列表（panels）
面板类型、站点分组名称、至少一个站点地址（url）为必填；站点说明（description）留空时会自动使用“站点1、站点2 ...”。
静态更新配置（update）
启用静态更新配置
关闭
默认关闭；开启后才会把静态更新配置写入 remote.config.json，并展开下面的版本、下载地址和更新说明表单。启用后生成的配置兼容所有版本客户端——旧版客户端会跳过 update 字段不影响站点地址读取，新版客户端才会解析并执行更新检测。
支持填写网盘页、官网发布页等手动下载跳转地址。客户端会优先使用自动更新下载地址；静态配置中的 Linux / macOS 自动更新都已拆分为不同架构。导入旧版 download_urls.linux 或 download_urls.macos 时会自动回填到对应架构输入框。
设为 true 时客户端会直接提示更新；设为 false 时仍会继续比较版本号。
设为 true 时客户端只能立即更新，不能关闭弹窗。

加密与密钥
请先完善必填项；如果不需要加密，可直接下载使用。首次加密建议点击“生成密钥并加密配置文件”，后续更新配置可填写原密钥后点击“使用当前密钥加密”。
首次加密请直接点击“生成密钥并加密配置文件”，系统会自动生成新密钥；如果是二次加密或更新配置，请在这里填写首次保存的密钥，再点击“使用当前密钥加密”，这样不会和旧密钥冲突。
上传时不要求文件名必须叫 remote.config.json，系统会按文件内容识别；只要是未加密的 JSON 配置对象即可。
